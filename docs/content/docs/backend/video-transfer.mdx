# 视频搬运

从工作区侧栏进入「视频搬运」，新建一条记录，再从表格操作列进入画布。记录属于当前账号，配置和结果存入服务端。此页面上传不设单文件大小上限，使用 8 MiB 分片上传，仍遵守账号每日上传额度和总存储容量；普通资源上传继续使用原单文件策略。

画布保留原视频输入节点和当前所选算法的一个处理节点。处理节点显示整体进度与当前阶段，完成后预览、下载所选时间范围的完整视频。服务端内部按 10 秒切段并有界并行执行，末尾保留不足 10 秒的有效画面；全部处理成功后按时间顺序合成完整输出，页面不展示片段节点或逐段下载入口。

上传会话在成功接收分片后续期 90 分钟，取消上传会释放未完成会话的配额和临时文件。网络重试沿用同一幂等标识，避免响应丢失后重复创建资源或扣减额度。

## 两条处理支路

| 支路 | 输入设置 | 适用范围 |
| --- | --- | --- |
| 固定水印 R16 | 原视频、固定角落或多个精确选区、参考时刻与有效时间 | 位置固定的亮色中性水印，标定后用空间连续性修复 |
| 移动水印 V6 | 原视频、参考时刻、参考帧中的像素选区、处理范围 | 形状稳定、以平移为主的水印，使用参考轮廓和字形身份验证、时序背景、可靠反算与空间补全 |

两条支路分别读取原视频，独立保存参数、状态与输出。切换支路不会把另一支路的结果作为输入。更换原片会重置两条支路；修改处理参数后需要重新运行。运行中的输入不能随意替换。

固定水印的手动模式可配置最多四个互不重叠的精确区域，每个区域分别指定参考帧、出现时间和持续时长，时长为 `0` 表示延续到片尾。参考帧必须位于该区域的有效时间内，框选应完整包含目标并排除其他文字与场景高光。配置精确区域后不再使用四角搜索。服务端内部切段共用同一组参考标定，不在新镜头里重新寻找另一处亮色图案。区域有效时间外不修改画面；有效时间内不能可靠确认目标时明确失败，不把漏处理帧当成完成。这些参数是调用方提供的约束，当前产品不会自动发现所有水印或自动推断出现区间。

移动水印的参考时刻使用原视频绝对秒数，可以位于处理片段之外。拖框坐标按原始视频像素保存，预览缩放不改变输入坐标。参考选区应紧密包含水印，并保留少量附近背景；旋转、明显缩放、换字和严重遮挡不属于当前跟踪器的可靠范围。

V6 对模板跟踪结果逐帧增加轮廓和字形身份复核，检查缺失笔画、可辨别的额外笔画及相同身份的竞争位置。穿过图案的背景线必须有外部连续同向边缘作为证据，不能把附近的无关平行线当作豁免条件。短边因像素锯齿产生方向偏差时，还会用整个图案范围外的可见直线提出方向，要求直线穿过原额外边缘，并通过相同的连续性检查，不直接放宽多余笔画的拒绝门槛。背景变化导致局部匹配失败，或运动预测使局部窗口不足以容纳模板时，重新搜索全图；短缺口另用前后独立验证的位置限定搜索范围，仍要求当前帧通过图像校验，不能直接用插值位置补成成功。轮廓搜索可以处理明暗极性变化，不能仅凭整体相关性较高就擦除相似字形。参考帧的近均匀边框是这些检查的输入条件。定位是否接受与背景能否恢复分别判断，背景切换不直接否定水印存在，但仍阻止跨切镜借用背景。

V6 优先使用通过背景配准、局部可见像素检验和两个独立来源一致性检查的时序像素。其余位置使用空间补全，复用 R16 的背景和边缘连续性求解，固定水印检测器不参与移动支路。背景取样排除水印及不确定边缘；大孔洞另尝试从原始干净图块合成纹理，平坦区域和细缝保留连续性求解。孔洞大小按完整的不可见区域判断，部分像素已有时序估计不会将其误判为细缝，最终仍只写入允许修补的位置。合成纹理不能作为真实干净背景再次参与标定，也不能证明已恢复被遮住的内容。局部像素、动态蒙版和标定结果使用有上限的缓存，算法不读取某个视频的预制轨迹。

处理时长为 `0` 表示处理至片尾。FFmpeg 按时间读取当前片段，输入可以是可变帧率，也可以有非零视频起始时间戳。输出保持原像素尺寸，以视频元数据中的平均帧率建立统一的恒定帧率时间轴；可变帧率输入会在解码时复制或丢弃帧，不保留原始不规则帧间隔。处理范围和参考时刻按这条输出时间轴取整到帧边界，秒数以视频画面起点为零。音轨按同一时间范围提取并编码为 AAC，视频使用 H.264，因此输出不是原文件的逐字节复制。旋转显示元数据和奇数尺寸仍会明确拒绝，不静默变更画面方向或分辨率。

算法只能利用可观察的背景证据；不透明水印遮住的真实内容无法保证还原，空间合成仍可能出现重复纹理、接缝或错误延伸的边缘。固定检测器可能混淆持续存在的明亮场景细节，移动跟踪也可能在部分帧失去可信位置。应分别检查漏检、误擦、背景失真和时间连续性；完成状态或 100% 跟踪覆盖率均不代表画面已经逐帧通过视觉验收。

`backend/tools/watermark/auto_overlay/discover.py` 是独立的自动候选发现研究入口，尚未接入页面任务。它从全画面稀疏采样中寻找位置固定、重复出现的轮廓，并生成候选区域与参考帧；候选不等于水印身份，也不是最终修复蒙版。移动、短暂出现和低对比目标仍可能漏检，场景文字与重复纹理可能误提，不能替代逐帧活动判断或声称能够通用自动去除。

## 配置运行环境

执行处理任务的后端需要 Python 3.10+、NumPy、OpenCV、FFmpeg 和 FFprobe。安装在独立虚拟环境，避免影响其他算法环境：

```bash
python3 -m venv .local/watermark-venv
.local/watermark-venv/bin/pip install -r backend/tools/watermark/requirements.txt
.local/watermark-venv/bin/python backend/tools/watermark/runner.py --check
```

`--check` 返回两个分支的依赖可用状态。服务端通过相同检查生成画布中的运行能力；缺少依赖时允许管理记录，但不能提交处理任务。

| 环境变量 | 用途 |
| --- | --- |
| `CANVAS_WATERMARK_PYTHON` | Python 可执行文件，留空从 PATH 查找 `python3` |
| `CANVAS_WATERMARK_RUNNER` | `backend/tools/watermark/runner.py` 的绝对路径；仓库根目录、后端目录及容器约定位置可自动发现 |
| `CANVAS_FFMPEG_PATH` / `CANVAS_FFPROBE_PATH` | FFmpeg / FFprobe 路径，留空使用 PATH |
| `CANVAS_WATERMARK_NATIVE_CACHE` | 可选的本机编译缓存目录 |
| `CANVAS_WATERMARK_DISABLE_NATIVE` | 设为 `1` 时禁用原生内核，使用 NumPy 数学实现，处理会变慢 |

R16 和 V6 空间修复优先编译并使用随源码提供的 C++17 内核；编译器由 `CXX` 或 PATH 中的 `c++` 提供。编译缓存写到临时目录或配置目录，不写入仓库。平台不支持的可选优化使用对应 NumPy 实现。Python 包就绪不代表原生加速已经启用。

已有 Release 镜像不会因为修改本地源码而自动增加该能力。部署到另一台机器时，需要在实际执行任务的后端环境安装运行器、依赖与编译器，并设置对应路径；不能只在浏览器所在电脑安装 Python。

## 执行与数据边界

任务使用既有持久化队列、进度、租约和取消机制，每个后端进程同时执行一批任务，批内默认并行处理两段，最多可配置四段。所有片段共享一份临时原片，按统一输出时间轴的绝对帧边界裁切，避免非整数帧率下重复或遗漏边界帧。启动前只读取媒体元数据，不再逐帧扫描整片时间戳或要求输入为恒定帧率；FFmpeg 在处理时读取当前片段和算法所需的有限参考、上下文。参考 ROI 和参考时刻始终以原片画面为准。解码与输出错误仍会明确报告。每段最多执行两小时，父任务预算随片段数增长。

取消会终止全部在途片段及合成阶段的 Python、FFmpeg 和算法 worker 子进程，保留已经发布的内部成功结果；租约失效的旧执行者不能写入状态，尚未发布的输出会清理。服务重启恢复同一任务时复用已成功片段；失败或取消后重新运行，只有原片、算法和设置与原任务一致时才复用成功片段，更换原片或参数会重新处理。临时输入和输出放在后端数据目录的临时子目录，结束后清理；输出先存入资源库，再以租约条件写入任务结果。

内部进度按各段实际帧数或时长加权，预留完整视频的合成与校验阶段，成片发布成功后才显示 100%。多段视频按时间顺序拼接，音轨从原片的整个处理范围连续提取一次，避免逐段 AAC 尾包在拼接处造成音画错位；合成后检查尺寸、帧数和时长。任一阶段失败都不把部分结果显示为完整成功。

失败节点显示去重、限长后的具体处理原因；已保存的历史失败任务也从内部结果读取原因，无需重新运行才能查看。错误内容不暴露本地路径或堆栈。失败时的帧数仅表示部分处理量，页面明确标注完整视频尚未生成；保存了一段输出也不代表其中水印位置与修复画质已经验收。

服务器默认不限制原片大小、原片时长和整次处理时长，像素量默认约 4K。管理员可通过 `CANVAS_WATERMARK_MAX_SOURCE_MB`、`CANVAS_WATERMARK_MAX_SOURCE_SECONDS`、`CANVAS_WATERMARK_MAX_PROCESS_SECONDS` 设置显式上限（0 表示不限），通过 `CANVAS_WATERMARK_MAX_PIXELS` 调整像素预算；实际能力由 API 返回。每个内部输出片段仍受生成文件大小策略约束，多段合成的完整视频不套用单个生成文件大小上限；两者都校验账号剩余容量和每日额度。已发布的内部结果与完整视频均占用存储空间。移动选区最多 196608 像素、单边最多 1024 像素。

默认每次请求使用 10 个 worker 总预算，可在画布中调整。服务器可通过 `CANVAS_WATERMARK_MAX_WORKERS` 下调上限，允许范围为 1 到 16；该预算在并行片段间均分。实际片段并发为 `CANVAS_WATERMARK_CONCURRENT_SEGMENTS`（默认 2）、worker 总数和片段数三者的最小值。移动分支内部的修复并发另有限制，不表示同时启动相同数量的跟踪器。移动结果会显示成功跟踪覆盖率，失去可信位置的帧保留原画面；完整成功输出允许修改像素数为 0。

记录采用 `revision` 乐观并发控制，旧标签页写入会返回冲突，不覆盖新的设置。任务提交与记录绑定在同一事务内；原片和输出参加资源引用保护。接口与表结构分别见 [HTTP API](/docs/backend/http-api) 和[后端数据库](/docs/backend/backend-database)。

算法实现、独立 CLI 参数、报告字段和小视频回归命令位于 `backend/tools/watermark/README.md`。独立运行器的 JSON 报告另有 `untrackedFrameDetails`，记录输出范围内未处理帧在统一输出时间轴上的绝对帧号、时间和实际拒绝原因；可变帧率输入的帧号不等于原文件中的压缩帧序号。最多列 100 项且受 32 KiB 字节预算限制，完整数量及是否截断分别由 `total`、`truncated` 表示。页面摘要显示聚合覆盖率，逐帧详情保存在运行器报告中。合成视频测试证明输入输出合同与核心路径可运行，不能替代复杂真实素材的画质验收。
